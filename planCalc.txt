plan calculation is Completely deterministic — it's Mifflin-St Jeor, the standard clinical BMR estimate. app/services/plan.py:75:

bmr = (10 * weight_kg) + (6.25 * height_cm) - (5 * age) + (-161 if is_female else 5)
calories = bmr * activity_multiplier        # 1.2 / 1.375 / 1.55
if goal == lose:  calories -= 500
if goal == gain:  calories += 300
calories = clamp(calories, 1200, 4000)

Then the macros (plan.py:89-92):

protein_g = weight_kg * 2                   # 2 g per kg bodyweight
fats_g    = calories * 0.25 / 9             # 25% of calories, fat = 9 kcal/g
carbs_g   = (calories - protein*4 - fats*9) / 4   # whatever's left


weightDeltaKg is just the gap to your target. targetDate assumes a steady 0.5 kg/week, a deliberately conservative rate (_KG_PER_WEEK, plan.py:34).

The 1200/4000 clamps (plan.py:32-33) exist so a strange input can't produce a dangerous target — this is health software, and 

At 206 kcal/day, a user trying to lose weight is off by roughly half a kilo every two and a half weeks, in the wrong direction. For a calorie-tracking app, that's the core value proposition being wrong.
